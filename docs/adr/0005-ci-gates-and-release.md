# CI is the only gate, and the release calls it

`.github/workflows/ci.yml` is the only definition of a green tree -- rustfmt, clippy, `cargo test --workspace`, `scripts/e2e.sh` against a real service, and `scripts/gui-smoke.sh` driving the GUI on a headless X server -- and it runs on every pull request and on `main`, one job per check so a red run names the check that failed. `release.yml` calls it as a reusable workflow, so a `v*` tag builds and publishes the static CLI tarballs and the AppImage only on a commit those jobs pass; `workflow_dispatch` on `release.yml` is a dry run (build and verify, publish nothing, keep the artifacts) because the packaging path has to be checkable without cutting a version. Both workflows get their system packages from `.github/actions/setup`, so the list gpui needs lives in one place rather than in every job.
